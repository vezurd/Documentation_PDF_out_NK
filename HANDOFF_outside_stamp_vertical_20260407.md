# Handoff — поля вне штампа, Origin/Stretch, выравнивание по высоте

**Дата:** 2026-04-07  
**Статус:** запросы пользователя зафиксированы; часть поведения реализована; **итоговый ожидаемый результат сессии пользователем не достигнут** (см. раздел «Что не закрыто»).

---

## Запросы пользователя (по хронологии / смыслу)

1. **Поле `50_File_Name_Stamp` (adapt_debug `adapt_debug_20260407_182448.txt`)**  
   При загрузке шаблона верхняя грань не совпадала по высоте с горизонталью через базовую точку Origin (`frame_bottom_right`).

2. **Уточнение модели**  
   Поля **вне штампа** должны по смыслу:
   - к **внешнему** краю листа прижиматься через **Stretch**;
   - к **рамке чертежа** прилегать через **Origin** (одна из базовых точек по выбору).

3. **Handoff**  
   Описать запросы, сделанные изменения и файлы; указать, что желаемый результат сессии **не достигнут**.

---

## Что сделано в коде

### Диагностика `50_File_Name_Stamp`

- Сверка `adapt_debug` JSON: `scene_rect` совпадает с `field_to_fitz_rect(..., padding_mm=0)` — **ошибки загрузки / рассинхрона маркера Origin с расчётом поля не выявлено**.
- Геометрия: при `frame_bottom_right` верх прямоугольника в pdfminer задаётся **v** в `bbox_mm`; в логе у поля **v для верхней грани ≈ 4.29 mm** → верх **намеренно выше** линии `frame.y0` на ~4.3 mm (~12 pt), а не на линии рамки.
- **Вывод:** это в первую очередь **данные шаблона** (или ожидание другой семантики Origin), а не баг `_snap_item_to_field_def` / маркеров.

### Реализация «прилипания» к рамке по высоте (вне штампа)

Добавлена явная операция и API, согласованная с формулировкой пользователя (Stretch = лист, Origin = рамка):

| Файл | Изменение |
|------|-----------|
| `pdf_parsing_v2/coord_transform.py` | Функция `snap_outside_stamp_vertical_to_frame(field, frame, eps_pts=...)`: для `outside_stamp` двигает **внутреннюю** горизонталь к `frame.y0` (origin снизу) или `frame.y1` (origin сверху); при одновременных Stretch `top`+`bottom` возвращает `None`. |
| `pdf_template_editor/properties_panel.py` | Кнопка «К линии рамки (высота)», подсказки у «Вне штампа», Origin, Stretch; включение кнопки при `outside_stamp` + открытом PDF с `frame_info`; обработчик `_on_snap_frame_vertical`. |
| `pdf_parsing_v2/test_snap_outside_vertical.py` | Юнит-тесты на snap (низ/верх рамки, отказ без `outside_stamp`, полностью внутри чертежа, оба вертикальных stretch). |
| `.cursor/rules/AI_memory.mdc` | Краткая строка про кнопку и `snap_outside_stamp_vertical_to_frame` в пункте `outside_stamp`. |

**Не трогалось:** движок извлечения, автоматический snap при загрузке шаблона, изменение семантики `bbox_mm` без явного действия пользователя.

## Что не достигнуто (почему «результат сессии не достигнут»)

- Пользователь ожидал **понятную/автоматическую** вертикальную привязку «как к рамке» без ручной подгонки **v** в мм и без отдельной кнопки — в текущей реализации это **частично** закрыто только **ручным** шагом («К линии рамки») и документацией в тултипах.
- Исходная претензия к **`50_File_Name_Stamp`** («при загрузке не выравнивается») **не устранена изменением данных** в репозитории: правка `bbox_mm` в шаблоне или использование новой кнопки в редакторе остаётся на стороне автора шаблона.
- Любые дополнительные пожелания (например, snap при загрузке, другая трактовка Origin только для `outside_stamp`, привязка к линии штампа `h_bottom` вместо `frame.y0`) **не реализованы** в этой сессии.
