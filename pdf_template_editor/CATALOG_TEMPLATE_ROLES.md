# Каталог полей и шаблон (StampTemplate): роли и источники данных

Документ для разработчиков и настройки процессов. Одни и те же сущности «поле» отражены **и в каталоге проекта**, **и в JSON шаблона** — удобство редактирования и переиспользования; **источник истины по колонкам разный**.

## Где что хранится

| Зона | Файл | Назначение |
|------|------|------------|
| Каталог | `catalog.json` (в папке проекта) | Справочник полей проекта: **id**, **label**, **group**, **#**, **description**, **default_field_type** (`FieldCatalogEntry`). |
| Шаблон | `*.json` шаблона | Размещение на листе и поведение извлечения: **bbox_mm**, **clean**, **validate_regex**, **padding_mm**, **is_anchor**, **outside_stamp**, **origin**, **stretch_to_page**, а также **id**, **label**, **field_type**, **expected**, **expected_text** в конкретном шаблоне. |

**Дублирование id / label / expected между каталогом и шаблоном** — осознанное: в каталоге задают «норму» проекта, в шаблоне — фактическое состояние для этого штампа. Редактор может подтягивать недостающее из каталога при загрузке шаблона (`merge`).

## Правило принадлежности данных (важно!)

| Колонка | Источник истины | Направление синхронизации |
|---------|----------------|---------------------------|
| `id` | Каталог | Каталог → шаблон |
| `label` | Каталог | Каталог → шаблон |
| `default_field_type` / `field_type` | Каталог | Каталог → шаблон |
| `expected` | Шаблон | Шаблон → каталог (отображение в UI) |
| `expected_text` | Шаблон | Шаблон → каталог (отображение в UI) |
| `bbox_mm`, `clean`, `validate_regex` и т.д. | Шаблон | Только шаблон |
| `group`, `#`, `description` | Каталог | Только каталог |

**Следствие для импорта из шаблона:** при импорте `label` и `field_type` из шаблона **не перезаписывают** каталожные значения — каталог является источником истины для них. Обновляются только `expected` и `expected_text` (шаблон-owned), отображаемые в таблице каталога для удобства.

## Источник при синхронизации каталог ↔ сцена

Реализация: `CatalogEditorPanel._merge_catalog_row_into_fielddef`, `compute_sync_to_template`, применение в `main_window._apply_catalog_sync_to_scene`.

**Из строки каталога (таблица) в поле шаблона на сцене передаются:**

- **id** (текст ячейки id)
- **label**
- **field_type** (из колонки field_type / `default_field_type`)
- **expected**, **expected_text** (колонки в таблице; в JSON каталога не сохраняются, но в UI правятся для удобства и затем уходят в шаблон при синхронизации)

**С поля на сцене не перезаписываются** (остаются из текущего `FieldDef` прямоугольника):

- **bbox_mm**
- **clean**, **validate_regex**
- **padding_mm**
- **is_anchor**, **outside_stamp**
- **origin**, **stretch_to_page**

То есть при push «семантика из каталога», «геометрия и тонкая настройка изображения/извлечения — из шаблона».

## Действие «Привязать строку к полю на canvas…»

Список в диалоге: **номер = `FieldRectItem.cell_index`**, совпадает с колонкой «#» в панели «Список полей» (тот же порядок сортировки). В строке комбобокса — **только id** поля (как в каталоге), без label.

Пользователь выбирает **какой прямоугольник на сцене** соответствует строке каталога. В выбранный `FieldDef` **записывается результат `_merge_catalog_row_into_fielddef`** (как в таблице выше): **данные из каталога** перекрывают id/label/тип/expected у поля, **остальное** остаётся от выбранного поля.

Строка каталога **не заполняется из шаблона** — наоборот, шаблон обновляется под каталог.

## JSON каталога

В `catalog.json` **не** хранятся **expected** / **expected_text** (источник для пайплайна — шаблон). В редакторе колонки expected всё равно есть для удобства и синхронизации с шаблоном.

## Действие «Импорт из шаблона» (кнопка в панели каталога, T7.2)

Интерактивный диалог `_ImportFromTemplateDialog` с двумя секциями:

**Секция 1 — существующие поля** (id уже в каталоге):
- Показывает только `expected` / `expected_text` (diff-подсветка: жёлтый = изменилось).
- `label` / `field_type` — информационно (может отличаться), НЕ изменяются.
- Галочки для выбора каких полей обновлять. По умолчанию скрываются строки без изменений («Показать без изменений»).

**Секция 2 — новые поля** (id нет в каталоге):
- Combo «Привязать к записи каталога»: выбрать существующую запись → canvas-поле получит `id`/`label`/`field_type` из каталога; `expected`/`expected_text` из шаблона.
- «— новая запись —»: создать новую запись в каталоге (поведение как раньше).

## Действие «Добавить поле на canvas» (контекстное меню каталога, T7.3)

Вместо размещения на фиксированном месте — активируется **place_mode** в `StampGraphicsView`:
- Курсор становится перекрестием, пунктирный прямоугольник следует за мышью.
- Клик: сигнал `place_confirmed(QRectF)` → `main_window._on_place_confirmed` создаёт поле.
- Escape: отмена.

## Синхронизация coverage (T7.1)

`_update_catalog_panel_coverage()` (подсветка зелёный/красный в таблице каталога) вызывается через дебаунс-таймер 100 мс (`_schedule_catalog_coverage_update`), который запускается из `_on_scene_changed` при изменении количества полей и из `_on_field_changed` при смене свойств. Это гарантирует обновление при удалении полей, рисовании, Ctrl+drag и любых будущих операциях — без ручного добавления вызова в каждый обработчик.

## Код

- Слияние строки + поля: `catalog_editor.CatalogEditorPanel._merge_catalog_row_into_fielddef`
- Сигнал привязки: `catalog_field_link_apply_requested` → `main_window._on_catalog_field_link_apply`
- Ссылка на canvas при переименовании id: `USER_ROLE_SYNC_LINK` на ячейке id (см. `AI_v2_editor.mdc`)
- Дебаунс coverage: `main_window._schedule_catalog_coverage_update` → `_catalog_coverage_timer`
- Place mode: `StampGraphicsView.set_place_mode` / `place_confirmed` → `main_window._on_place_confirmed`
