# Отчет по работе программы сравнения тегов оборудования

## Назначение программы

Программа предназначена для автоматизированного сравнения тегов оборудования из RFP (Request for Proposal) с актуальными данными МТО (Материально-техническое обеспечение) и вендорской документацией VO (Vendor Documentation).

## Основные этапы работы

Программа выполняет четыре основных этапа обработки данных:

1. **Этап 1: Загрузка и проверка данных RFP**
   - Загрузка данных из файла "Сводная RFP.xlsx"
   - Проверка на дублирование тегов
   - Проверка соответствия количества тегов значениям в колонках VALUES и VALUES_2

2. **Этап 2: Загрузка данных MTO**
   - Сканирование директории с файлами МТО
   - Проверка соответствия title_system между RFP и MTO файлами
   - Загрузка данных из файлов МТО с группировкой по title_system

3. **Этап 3: Загрузка данных VO**
   - Загрузка данных из вендорской документации (в разработке)

4. **Этап 4: Анализ и сопоставление**
   - Проверка данных MTO на дублирование тегов и несовпадения с VALUES
   - Сопоставление строк RFP с данными MTO по тегам
   - Определение статуса позиций
   - Проверка сумм VALUES для контроля целостности данных

## Выходные документы (Папка результатов)

Все результаты работы программы сохраняются в папке с названием `_результат_проверки_ГГГГ.ММ.ДД.ЧЧ.ММ`, которая создается в той же директории, где находится исходный файл RFP.

### Список выходных документов

1. **Отчет по дублям тегов - RFP_ГГГГММДД_ЧЧММСС.xlsx**
   - Этап: Этап 1
   - Назначение: Выявление дублирующихся тегов в RFP
   - Комментарий: Содержит строки из RFP, в которых обнаружены повторяющиеся теги. Файл отсортирован по тегам с цветовой маркировкой для удобства анализа. Помогает выявить ошибки в исходных данных RFP.

2. **Отчет по несоответствию тегов - RFP_ГГГГММДД_ЧЧММСС.xlsx**
   - Этап: Этап 1
   - Назначение: Проверка соответствия количества тегов и значений
   - Комментарий: Содержит строки, где количество тегов не совпадает с числовыми значениями в колонках VALUES или VALUES_2. Ячейки с несовпадениями выделены желтым цветом, совпадающие - зеленым.

3. **Шаг2_MTO_сравнение_title_system_ГГГГММДД_ЧЧММСС.xlsx**
   - Этап: Этап 2
   - Назначение: Сравнение системных обозначений
   - Комментарий: Таблица сравнения title_system между данными RFP и MTO файлами. Показывает, какие системы присутствуют в обоих источниках, какие только в RFP, а какие только в MTO. Цветовая индикация: зеленый - совпадение, красный - отсутствует в MTO, желтый - отсутствует в RFP.

4. **Шаг2_MTO_результаты_загрузки_ГГГГММДД_ЧЧММСС.xlsx**
   - Этап: Этап 2
   - Назначение: Статистика загрузки MTO файлов
   - Комментарий: Отчет о результатах загрузки каждого файла MTO: имя файла, title_system, статус загрузки (успешно/ошибка/пустой), количество загруженных строк, описание ошибок (если есть).

5. **Отчет по дублям тегов - MTO_ГГГГММДД_ЧЧММСС.xlsx**
   - Этап: Этап 4.1
   - Назначение: Выявление дублирующихся тегов в MTO
   - Комментарий: Детальный отчет о тегах, которые встречаются более одного раза в данных MTO. Для каждого вхождения указаны: тег, количество вхождений, title_system, CODE, MTO_NAME, DS_TITLE, номер строки. Помогает выявить ошибки в данных MTO.

6. **Отчет по несоответствию тегов - MTO_ГГГГММДД_ЧЧММСС.xlsx**
   - Этап: Этап 4.1
   - Назначение: Проверка соответствия тегов и VALUES в MTO
   - Комментарий: Содержит строки из MTO, где количество тегов не совпадает со значением в колонке VALUES. Включает полный список тегов с переносами строк для удобства анализа.

7. **Шаг4_Сопоставление_RFP_MTO_ГГГГММДД_ЧЧММСС.xlsx**
   - Этап: Этап 4.6
   - Назначение: Итоговое сопоставление данных
   - Комментарий: **Главный результат работы программы.** Содержит объединенные данные RFP и MTO с информацией о сопоставлении. Включает: все колонки из RFP, статус наличия тегов в RFP, статус позиции, статус сопоставления, данные из MTO (теги, коды, наименования, типы, количества, значения). Используется для дальнейшего анализа и принятия решений.

8. **Шаг4_Проверка_сумм_VALUES_ГГГГММДД_ЧЧММСС.xlsx**
   - Этап: Этап 4.5
   - Назначение: Контроль целостности данных
   - Комментарий: Проверка сумм значений VALUES по title_mark для исходных данных RFP и MTO, а также для результата сопоставления. Выявляет расхождения, которые могут указывать на ошибки в процессе сопоставления или в исходных данных. Статус "OK" - суммы совпадают, "ОШИБКА" - обнаружены расхождения.

## Описание статусных столбцов таблицы "Сопоставление_RFP_MTO"

В файле `Шаг4_Сопоставление_RFP_MTO` (файл №7) присутствуют три статусных столбца, которые помогают понять результат сопоставления данных. Эти столбцы расположены между данными RFP и данными MTO и имеют цветовую маркировку (желтый фон заголовков).

### 1. Столбец "Фильтр по тегам" (HAS_TAGS_RFP)

Указывает, есть ли теги в строке RFP. Используется для фильтрации строк при анализе.

    1.1. **"Да"**
        - Описание: В строке RFP присутствуют теги. Такие строки участвуют в сопоставлении с MTO по тегам.

    1.2. **"Нет"**
        - Описание: В строке RFP отсутствуют теги. Такие строки не участвуют в сопоставлении по тегам (могут быть позиции без тегирования).

    1.3. **"Нов."**
        - Описание: Строка добавлена из MTO и отсутствовала в исходном RFP. Это означает, что в MTO был найден тег, которого не было в RFP.

### 2. Столбец "Статус позиции" (POSITION_STATUS)

Определяет статус позиции относительно наличия данных в MTO и возможности сопоставления. Устанавливается для строк RFP, которые не были сопоставлены по тегам на этапе прямого сопоставления.

    2.1. **"" (пусто)**
        - Описание: Статус не установлен.
        - Условие установки: Устанавливается для строк, которые:
            - Уже были сопоставлены по тегам (MATCH_STATUS = "Тег сопоставлен")
            - Не имеют тегов в RFP
            - Добавлены из MTO (MATCH_STATUS = "Добавлен из МТО")

    2.2. **"Исключен"**
        - Описание: Позиция исключена из обработки.
        - Условие установки: Устанавливается когда общее количество позиций в MTO (с тегами + без тегов) меньше требуемого количества из RFP для данного CODE. Это означает, что в MTO недостаточно позиций для покрытия требований RFP.

    2.3. **"Не протегирован в МТО"**
        - Описание: Позиция найдена в MTO, но без тегов.
        - Условие установки: Устанавливается когда:
            - Не хватает позиций с тегами для покрытия требований RFP
            - Но есть позиции без тегов
            - И общее количество позиций в MTO достаточно
        - Дополнительно: В этом случае данные из MTO (без тегов) добавляются в строку RFP с поправкой на количество.

**Примечание:** Статус "Не протегирован в RFP" упоминается в комментариях кода, но в текущей версии программы не используется.

### 3. Столбец "Статус сравнения ТЕГОВ" (MATCH_STATUS)

Показывает результат сопоставления тегов между RFP и MTO. Это основной статус, определяющий успешность сопоставления.

    3.1. **"Тег сопоставлен"**
        - Описание: Тег из RFP успешно найден и сопоставлен с позицией в MTO.
        - Цвет строки: Зеленый
        - Условие установки: Тег из строки RFP найден в MTO для соответствующего title_system. Данные из MTO добавлены в строку.

    3.2. **"Не найден в МТО"**
        - Описание: Тег из RFP не найден в MTO.
        - Цвет строки: Желтый
        - Условие установки: Тег присутствует в RFP, но отсутствует в MTO для соответствующего title_system. Данные MTO не заполнены.

    3.3. **"Добавлен из МТО"**
        - Описание: Строка добавлена из MTO, так как тег был в MTO, но отсутствовал в RFP.
        - Цвет строки: Бирюзовый
        - Условие установки: Тег найден в MTO, но отсутствует в RFP. Создается новая строка с данными из MTO.

### Взаимосвязь статусных столбцов

Статусные столбцы работают совместно для полной характеристики строки:

- **"Фильтр по тегам" = "Да"** + **"Статус сравнения ТЕГОВ" = "Тег сопоставлен"** → Успешное сопоставление по тегам
- **"Фильтр по тегам" = "Да"** + **"Статус сравнения ТЕГОВ" = "Не найден в МТО"** + **"Статус позиции" = "Исключен"** → Тег не найден, и позиций в MTO недостаточно
- **"Фильтр по тегам" = "Да"** + **"Статус сравнения ТЕГОВ" = "Не найден в МТО"** + **"Статус позиции" = "Не протегирован в МТО"** → Тег не найден, но используются позиции без тегов из MTO
- **"Фильтр по тегам" = "Нов."** + **"Статус сравнения ТЕГОВ" = "Добавлен из МТО"** → Новая строка из MTO, которой не было в RFP

### Рекомендации по использованию статусов

1. **Для анализа успешности сопоставления:** Фильтруйте по столбцу "Статус сравнения ТЕГОВ" = "Тег сопоставлен"
2. **Для выявления проблемных позиций:** Ищите строки со статусом "Не найден в МТО" или "Исключен"
3. **Для проверки новых позиций:** Используйте фильтр "Фильтр по тегам" = "Нов." для поиска позиций, добавленных из MTO
4. **Для анализа позиций без тегов:** Фильтруйте по "Статус позиции" = "Не протегирован в МТО"

## Примечания

- Все файлы содержат временную метку в формате `ГГГГММДД_ЧЧММСС` для идентификации конкретного запуска программы
- Файлы используют цветовую маркировку для быстрой визуальной оценки результатов
- Все таблицы содержат автофильтры и закрепленные заголовки для удобства работы
- Папка результатов автоматически открывается после завершения работы программы (если она не пуста)

## Рекомендации по использованию результатов

1. **Начните с файла №7** (`Шаг4_Сопоставление_RFP_MTO`) - это основной результат работы программы
2. **Проверьте файлы №1 и №2** для выявления ошибок в исходных данных RFP
3. **Используйте файл №3** для понимания соответствия систем между RFP и MTO
4. **Анализируйте файлы №5 и №6** для выявления проблем в данных MTO
5. **Контролируйте файл №8** для проверки целостности данных после сопоставления
